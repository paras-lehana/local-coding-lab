# RTX 3080 / 64 GB: what has actually been measured

Evidence date: 14 October 2026. This is a reviewed public digest of earlier
private experiments. Private instruction contents and raw chats are not
published. Source report hashes and selected numerical evidence are in
[historical-results.json](historical-results.json). These numbers were **not**
produced by the new public router-v1 benchmark or portable launcher.

## Workstation and requirements

Windows 11, Ryzen 7 5800X, RTX 3080 10 GB, 63.91 GiB usable RAM. GPU/CPU stock;
RAM 2800 was the owner's accepted condition. Earlier system crashes remain
unexplained: no causal conclusion about memory clocks is supported. Apps stay
open. Free memory changes materially during the day. All model assets stay on
the dedicated installation drive. Maximum whole-prompt time is 20 minutes.

The coding requirement is instruction/file grounding across `.github`, `.claude`,
linked rules, code and docs, with long-chat continuity. Passing a syntax check
or recalling a path name is insufficient. The model must actually receive/read
the relevant content, handle stale versions and admit missing information.

## Thinking-budget diagnostic on unchanged Qwen Q4 weights

All completed runs received the same 5721-token inline source/question fixture.
Seed 73, temperature 0.6, output cap 8192. Runtime b11562. The code task was a
known regression, not a held-out test. Budgets were verified by re-tokenizing
delivered reasoning. They are runtime ceilings, not native xhigh modes.

| Context / CPU expert layers | Budget | Wall s | First final s | Prefill tok/s | Decode tok/s | Code |
|---|---:|---:|---:|---:|---:|---|
| 64K / 33 | 0 | 136.22 | 36.80 | 156.62 | 10.34 | 3/7 |
| 64K / 33 | 512 | 161.95 | 77.31 | 157.92 | 11.88 | 5/7 |
| 64K / 33 | 2048 | interrupted | none | incomplete | incomplete | unscored |
| 32K / 32 | 2048 | 264.95 | 200.97 | 164.37 | 12.44 | 7/7 |
| 32K / 32 | unrestricted | interrupted | none | incomplete | incomplete | unscored |

The 0-budget answer mishandled type conflicts and retained mutable aliases.
The 512 answer improved value behavior but still shared nested mutable objects.
The 2048 completed answer handled all seven code checks, including isolation.
**All completed answers still had instruction-loading/citation problems.**
Claude's real imports must not be confused with arbitrary Markdown links or
loading behavior in another agent. Inline delivery did not test autonomous reads.

Because context and expert placement changed before the completed 2048 run,
this is not an otherwise-controlled four-way reasoning comparison. All completed
code was syntactically valid: quantization alone cannot explain these differing
semantic outputs, though these tests do not isolate its causal effect either.

## Memory and stops

The 32K profile allocated 5311.13 MiB GPU model weights, 15787.52 MiB host model
weights, 340 MiB KV (68 CPU / 272 GPU) and 62.81 MiB recurrent state. Process
working set peaked around 16.38 GiB during the completed 2048 run. A valid
separate 64K counter snapshot measured 5.880 GiB dedicated process VRAM.
Total GPU use includes desktop applications and must not be called model VRAM.

Two controlled server stops occurred at 2.352 and 2.199 GiB free physical RAM.
There was no new OS boot or matching WHEA event in that trial window. The later
restoration attempt was refused at 16.7 GiB free RAM versus a 20.5 GiB preload
gate. A repository-preparation snapshot later showed 23.25 GiB free RAM; that
does not erase the earlier stops or prove continuous fit.

All-RAM KV and 512 MiB expert-cache profiles were **prepared, not loaded or
benchmarked** after the stops. Continue UI remains unverified. No candidate
weights were downloaded or model settings changed while creating this repo.

## Takeaway

Qwen Q4 remains a useful measured reference, with known code and grounding
failures. Gemma QAT is worth testing for headroom, not because it has already
proved smarter. GLM UD-Q4 is a conditional cross-family comparison. Bigger
context, higher weight precision and preserved reasoning are separate variables;
none guarantees reliable file understanding. Use the [next plan](../docs/next-experiments.md).
