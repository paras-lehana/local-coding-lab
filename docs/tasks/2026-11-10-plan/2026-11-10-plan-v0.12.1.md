## 1. Decision and purpose

Keep the retained **Qwen3.6-35B-A3B UD-Q4_K_M** as the reference artifact. Do not
call it a proven overall winner: its historical instruction/public results are
stronger than its incomplete coding coverage, and the currently prepared
apps-open profiles are new configurations. First finish reviewing the answers
already collected. Then resolve the small number of uncertainties most likely
to change the choice, before buying another several hours of native reasoning.

The objective is **correct, source-grounded repository work**: the model follows
the right instruction files, reads actual code and documentation, notices changed
files, admits missing information, and delivers runnable changes. Long context
and higher precision are means of achieving that objective, not scores by
themselves. Long accurate coding is acceptable. An instruction-free greeting
that produces no useful answer within 600 seconds fails the owner's practical
gate. Preserve the historical 1,200-second comparison cohort separately.

The proposed order is:

1. Close the existing Flint evidence and fix evaluation gaps offline.
2. Establish a fresh, complete Qwen reference and short matched memory controls.
3. Finish targeted Flint reasoning/output/residency controls while its weights exist.
4. Qualify the already-downloaded Flash-Next Q2 on changed, explicitly identified
   Strata settings and ordinary llama.cpp before adding speculative complexity.
5. Test Gemma12 Q6 against the retained QAT artifact, then official Flint INT4;
   rotate other higher-precision artifacts only after their controls are recorded.
6. Complete the dense27B, Gemma31, Coder-Next80, Coder30, K2 and other candidate
   coverage using explicit admission and screening decisions.
7. Run full, repeated, held-out and editor/lifecycle checks only for finalists.

This is a multi-day research programme, not a promise that every cross-product
will finish overnight. A failed dependency changes a row's status; it does not
erase that row or turn an untried model into a quality failure.

### Corrections carried into the new plan

- Q6 does not guarantee valid syntax; native/xhigh reasoning does not guarantee a
  correct answer. Quantization effects need matched measurements.
- Qwen3-Coder-30B-A3B is MoE, not dense. Coder-Next80 and original Next80-Instruct
  are distinct models. IFM K2 Horizon MoVA is not Moonshot Kimi K2.
- Installed64GB RAM plus10GB VRAM is not a single freely interchangeable74GB
  pool. Windows/apps, compute buffers, pinned allocations, mappings and commit
  limits matter. Available RAM already includes reclaimable standby memory.
- KV in RAM is not permanent conversation memory. The client must send the
  history/source contents; sleep/restart can discard cache. Reopen changed files.
- `--offload-kqv` is not a portable command meaning “put KV in RAM.” Inspect the
  pinned runtime's actual supported no-KV-offload option and allocation logs.
- Typical llama.cpp cache buffers reserve capacity at load. Token occupancy may
  grow without the allocation growing. Strata dynamic growth is a separate mode.
- A model receiving2K tokens with a72K setting has not passed a72K test. A model
  finding three needles has not passed repository coding at that length either.
- GPU memory occupancy is not GPU compute utilization. Filling the final3GB can
  displace useful cache or remove desktop headroom without improving answers.
- The prepared Qwen res7/res10 profiles change reserve and admission settings
  too. Create a matched pair before calling their difference a residency effect.
- The current coding wrapper does not expose seeds74/75 even though its lower
  collector does. Implement and verify seed forwarding before claiming repeats.

## 3. Team, ownership and execution boundaries

Use four roles. The coordinator may also be the inference operator, so this fits
four concurrent agent slots. More agents do not create more GPU capacity.

| Role | Owns | May do while inference runs | Must not do |
|---|---|---|---|
| A — Coordinator/operator | Queue, manifests, admission, one native engine, cancellation, state transitions | Read telemetry, save checkpoints, communicate results | Grade/build/download/hash large weights concurrently; start two engines |
| B — Source/compatibility reviewer | Publisher identity, runtime support, pins, licenses, artifact/disk plan | Small source/web reads and document drafts | Install/load/update runtime or use paid APIs |
| C — Evaluator | Frozen/held-out fixtures, source reviews, isolated graders, result checks | Read completed visible responses; prepare reviews without execution | Execute candidate code on Windows or run graders beside inference |
| D — Skeptical reviewer/reporter | Comparison audit, article claim ledger, publication, independent scoring review | Review small receipts and draft docs | Edit raw results, silently change rubric, declare a score before evidence |

Only A may launch or stop an engine. B/C/D request jobs by writing a proposal;
they never execute it. During downloads, full hashes, builds and grading, the
native inference slot is empty. Pause large repository scans and installers
during measured runs. Research network traffic must not include model downloads.

The existing process check is not an atomic cross-launcher lock. Until a tested
lease is implemented, a **single designated operator and serial dispatch** are
mandatory. The lease is a planned implementation task, not an existing feature.
It must record owner PID, creation time, runtime/model identity and job ID;
stale-lock recovery must verify process absence rather than delete a lock blindly.

### Non-negotiable operating conditions

1. Keep applications open. Do not kill processes to meet an admission threshold.
2. Keep current CPU-affinity protections and clocks. Record conditions; do not
   alter RAM/CPU/GPU tuning, drivers, BIOS, TDR, power policy or pagefile settings.
3. Use physical `E:\llm` destinations. Inspect junction targets before downloads.
4. Keep retained Qwen Q4 and its verified working runtime until a successor passes.
5. Experiments use8081; production uses8080. An idle health endpoint does not prove
   an owner chat is inactive between tool turns. No forced production interruption.
6. Keep existing profile admission requirements and stop floors, at minimum
   RAM2.5GiB, commit1GiB, device-free VRAM400MiB and the recorded84°C ceiling.
   These are emergency floors, not target utilization. Prefer≥1GiB device margin
   for an interactive finalist; report when that is not achieved.
7. A telemetry parse/query failure stops admission. A new monitored hardware
   event stops the owned run and is handed to the incident agents. Do not reset

8. No generated code execution before source review, and then only the existing

9. No editor typing/reload under the current user constraint. API qualification

## 4. Experiment record and restart procedure

Every job gets a unique ID such as `N10-FL-R4096-S73-A`. Never reuse a directory.
Store raw evidence under `local-data/2026-11-10-phase2/<job-id>/`. Store only
sanitized aggregates and public synthetic fixtures in Git.

This example is deliberately **not executable** and contains required identity
placeholders. A future executor fills them from receipts, resolves dependencies,
checks the exact command and only then creates an executable job. The plan-only
task leaves `inference_allowed=false` throughout.

State progression:
`planned → prepared → admitted → collecting → stopped → reviewed → graded → recorded`.
Alternative terminal states: `capacity-rejected`, `unsupported`, `unavailable`,
`output-limited`, `deadline`, `transport-error`, `hardware-stopped`, `deferred`.
`collected` is not `graded`; `graded` is not `promoted`.

After a reboot or conversation reset:

1. Read this plan, current project/shared instructions and newest task log.
2. Read the job manifest, last live telemetry, process receipt and stop receipt.
3. Check PID **and creation time, ancestry, executable and command line**. A stale
   `running` JSON is not proof of a live process; PID reuse is possible.
4. Inventory llama/Strata native/frontend processes and Ollama's loaded models.
   An unknown/failed inventory prevents launch. Never kill by process name.
5. Preserve partial streams. Do not synthesize a final answer from reasoning.
6. Classify the stop. Unfinished answers remain unscored. Query the same expanded
   event guard; do not make an incident disappear by choosing a later timestamp.
7. Only after a normal stop or an explicitly reviewed recovery, resume at the next
   unmet dependency in a new directory. Hardware/unknown-owner/failed-cleanup
   states remain review-required; they never automatically dispatch another model.
   Do not replay completed
   tasks or run the whole old queue merely because a wrapper exited.
8. Save a short checkpoint: done IDs, running ID/PID or none, next ID, blocker,
   evidence locations and current weight-retirement state.

## 5. Workload contract and success measures

### Existing comparison cohorts

| Cohort | Deadline | Purpose | Scoring rule |
|---|---:|---|---|
| `frozen-1200` |1200s whole workflow | Preserve historical comparison | Only complete compatible suites enter existing ranking |
| `extended` |Explicit, normally21600s whole workflow | Owner accepts slower accurate instruction-heavy work | Report separately; no retroactive frozen pass |
| `diagnostic` |Within the old1200s ceiling | Isolate a setting, short/cached probes | No full-suite score for a subset |
| New held-out fixture version |Fixed before collection | Generalization beyond extensively inspected old tasks | Separate fixture table; compatible stored cohort chosen by allowance |

Diagnostic **purpose** and stored **cohort** are separate fields. A capped,
cached or selected-task control allowing1800/21600s belongs to `extended` under
the maintained scorecard policy, with its diagnostic purpose in conditions.
Do not silently create a new scorecard cohort name for held-out fixtures.

A whole workflow includes prefill, reasoning, tool calls and final text. Output
limits and reasoning ceilings are independent of wall deadlines. The latter
ceiling is often per request/tool turn; record the effective policy. Client
`max_tokens` may override the server default. A native reasoning field being
accepted by HTTP is not proof that it worked.

### Measurements required for every relevant row

| Dimension | Record | Do not substitute |
|---|---|---|
| Identity | Weight/runtime/template/profile/fixture/request hashes | A friendly model label |
| Completion | Final tool-free answer, finish reason, all tool turns, stop receipt | First streamed reasoning token |
| Timing | Load; first event; first reasoning; first visible content; final-answer start; total; prefill/decode split | Cached decode tokens/s alone |
| Source use | Requested path, returned bytes/ranges/hash, successful read, source-backed claims, stale/missing facts | Tool-call success flag or a claimed read inventory |
| Code | Parse/compile, independent behavior groups, mutation/edge failures, model-written test defects | Syntax alone or model's own tests |
| Context | Total configured cells; actual rendered/tokenized input; output reserve; cached/new tokens; truncation | File count, window label or configured131K |
| Memory | Before/during/after available RAM and commit; model WS/private commit; device VRAM; KV buffers/cells; expert cache | Summing overlapping counters into model RAM |
| Paging/I/O | Process faults plus system hard-page reads and volume throughput/latency, scope and interval | Page faults alone as proof of SSD paging |
| Robustness | Fresh load, repeated prefix, changed prefix/file, cancellation, sleep/wake, endpoint ownership | A single `/health` response |

Use the existing telemetry cadence first; document any added sampling overhead.
Do not flush Windows caches or close applications to manufacture cold results.
Call a new server “fresh-process”; call only a genuinely uncached token prefix
“uncached-prefix.” Record that OS file cache may already be warm after hashing.

the unchanged `intervals`, `ttl_lru`, `js_pool`, `js_merge` questions and the public

for one defect if it could still improve instruction-heavy accuracy. Stop its
unchanged configuration after a600s plain-greeting failure or a resource/event

If any answer is incomplete, retain component results and completion coverage,
but omit the corresponding full-suite total. A failed completed implementation
is different from an incomplete answer or a broken grader.

`100 × (0.5 × private/36 + 0.3 × public/60 + 0.2 × coding/12)` only when all
components are complete and compatible. Do not renormalize missing components.
There is no complete frozen-cohort leader at this planning snapshot. Extended
results can guide a practical recommendation but must remain labelled extended;
changing the leaderboard's ranking policy would be a separately documented change.

## 11. Failure classification and decision rules

| Code | Meaning | Required handling |
|---|---|---|
| A-INTEGRITY | Model/runtime/profile hash mismatch | Do not load; resolve correct artifact |
| A-CAPACITY | RAM/commit/VRAM/disk admission refusal | Record required and actual values; no quality score |
| A-SUPPORT | Architecture, tensor, cache format or option unsupported | Exact error/source; different compatible configuration is a new row |
| A-IDENTITY | Model name has no verified official artifact | Source/date and unrun status; no substitute alias |
| R-RESOURCE | Floor/thermal/telemetry failure | Stop owned run; preserve partial answer unscored |
| R-HARDWARE | New monitored device/restart event | Stop and hand to incident agents; record association, not proven cause |
| C-NOANSWER | Empty/output-limit/deadline/tool-limit | Count incomplete; no delivered-code grade |
| C-TRANSPORT | Disconnect/protocol/cancellation failure | Compare client/native state; don't assume firewall or model failure |
| Q-SYNTAX | Delivered code cannot parse/compile | Original unchanged source/hash and actual compiler result |
| Q-BEHAVIOR | Delivered code violates contract | Independent counterexample and check group |
| Q-GROUNDING | Unsupported facts/citations/read/test claims | Claim versus successful returned bytes; keep private evidence private |
| Q-FRESHNESS | Old source presented as current | Distinguish no reread from incorrect interpretation after reread |
| Q-FORMAT | Wrong fences/schema/count/extra text | Separate from behavior and source accuracy |
| G-INFRA | Sandbox/compiler/process-creation failure | No model score; at most one unchanged serial retry with both receipts |
| G-REVIEW | Ambiguous source selection/unparseable grade | Resolve intended candidate before execution; don't pick by passing score |
| D-DEFERRED | Useful but unmet dependency/redundant/currently too costly | Exact reason, next trigger and last checked date |
