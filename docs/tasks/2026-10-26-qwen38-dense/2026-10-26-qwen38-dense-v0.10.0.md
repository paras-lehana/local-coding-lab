## What to measure next

27October metadata check pins three practical GGUF options from
`unsloth/Qwen3.8-27B-GGUF` revision`4ca720788d1e01f1bff70c033e0d0028fd02e502`:

| Artifact | Bytes | Intended role |
|---|---:|---|
|UD-Q4_K_M|16464440224|Initial smaller-weight qualification with native xhigh; medium is a distinct effort control|
|UD-Q6_K, plain|21983677344|Higher-precision follow-up after a complete qualified dense workflow|
|UD-IQ4_XS|14252845984|Smaller-memory fallback if Q4 cannot qualify; no equivalent-quality claim|

Publisher LFS hashes are recorded in the catalog; no weight bytes were downloaded
during Flint inference. These entries do not prove local integrity, compatibility
or fit. Before inference, verify full files and the actual GGUF layout/template,
then calculate layer placement from tensors rather than a universal layer count.
The plain Q6 is not one of the differently sized Q6_K_M/L/XL files in the same
repository. The smaller Q4 is chosen to address the old high-residency barrier;
the extended allowance and native effort controls address a different barrier,
answer completion. Neither change proves better intelligence in advance.
[Pinned quant repository](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF/tree/4ca720788d1e01f1bff70c033e0d0028fd02e502).

The publisher's architecture also lets us estimate the full-attention KV
component before loading:16attention layers,4KV heads,256dimensions and
separate K/V. At32K tokens, f16 is2048MiB; q8_0 including its block scales is
1088MiB. At128K, those components become8192MiB and4352MiB respectively.
These are calculations for a complete logical cache, not measured allocations
of a new run. Recurrent GDN state, checkpoints, padding, batch buffers and
backend placement add their own costs. With partial layer offload, the actual
CPU/GPU split must come from runtime logs; putting all KV on the host moves
this cost rather than removing it. The generic claims that every32K model
needs16GiB KV, or that128K q8 always needs8GiB, do not apply.

For an initial dense retry, fit32K before attempting128K. A larger generated
answer budget may require a separately larger context even on a short task;
reserve room for both supplied files and the answer. Sparse-MoE expert-cache
flags are not a dense-model optimization. The useful variables here are actual
layer placement, weight quant, KV format/location, batch size and the model's
native effort, each with separate completion and correctness evidence.

1. Plain no-file greeting cold/warm, separately from editor-injected instructions.
2. Frozen public/private source-routing and coding tasks with native xhigh effort.
   Extended diagnostics are permitted by the owner's26October clarification;
   old1200second failures retain their status.
3. Repeated common prefix versus a changed middle file; confirm both reuse and
   correct refreshed values. Cache hits alone do not prove correct retrieval.
4. MTP off/on and short-long-short request sequences, complete tool-call JSON,
   final-answer delivery and isolated code checks.
5.32K qualification followed by64K/128K actual populated context; quantify RAM,
   commit, VRAM, KV allocation, prompt processing and whole-task latency.

## Recommendation for this and other machines

For this PC, prioritize an engine/placement change with a demonstrable10GB fit
before importing a24GB recipe. Do not redownload the oldQ6/Q8 solely to repeat
an unchanged failure. Higher precision and long diagnostic time are valid
options if a fresh fit and greeting pass. AirLLM is an offline full-precision
control candidate, not yet a daily coding recommendation.

For24GB Ampere, HyperQwen is a stronger reproduction target because its measured
residency matches that capacity. For16GB Blackwell, the5070Ti recipe is relevant
but its modified checkpoint and kernel patch must remain distinct variables.
For all hardware, publish actual task completion and correctness alongside
throughput. None of these articles proves universal syntax correctness or
permanent memory of files excluded from the prompt.

New downloads, compilation and model quality trials for these dense routes
remain unrun. Reasons: finish the current campaign, reserve enough disk for
weights/splitting, and establish a supported allocation within available RAM
and VRAM. Source provenance is archived privately and linked in the review.
