Local measurements and limitations belong in the

## What changes

The article combines several independent ideas. TQ weight formats rotate and
compress weights. Low-bit KV compresses attention history. DFlash2 proposes
several output tokens for target verification. Prefix reuse avoids processing
unchanged earlier input again. azllm adds serving-layer streaming and progress
reporting to tqllm; its author explicitly says the engine/formats/sampling are
unchanged. This is not a new trained model or an automatic intelligence gain.

TQ3_4S stores32weights in16bytes, including scales:4.0bits/weight for those
blocks. The complete27B file mixes tensor types and averages about4.24bpw.
Calling this simply “3-bit” and equating it to IQ3_M is incorrect. The published
11.85GB TQ_XS uses another format and is described by the publisher as weaker
for coding/instructions; it is not a no-cost way to reproduce TQ3_4S quality.

The headline and the article's main table also use different weight variants.
The upstream current README separates them. Its prompt filler and capped
outputs are throughput probes, not our linked-instruction/code benchmark.
One146K prompt and a262K capacity setting do not prove reliable262K retrieval.

## The10GB constraint

Our PC has10,240MiB dedicated VRAM, partly occupied by normal applications.
`src/qwen35.cpp:g_mat/g_cat` uploads dense body matrices through the GPU
uploader. `src/model.cpp:load_fitted` can move embeddings, an output-head copy
and KV to host memory, reduce buffers and context, but offers no general dense
layer CPU backend. `-ncmoe` concerns MoE experts; this27B target is dense.
Those host moves happen after initial weight loading, another relevant peak.
The retrieved TQ3_4S-v2 header measures12,185,839,616bytes (11.349GiB) for
the64main blocks alone, excluding embeddings, output head and the optional
prediction block. This particular body exceeds the entire physical GPU;
file size alone is not used as an exclusive model-VRAM measurement.
This is a capacity limitation, not a minimum-VRAM check to delete.

KV-to-RAM is real: `--kv-host` and `--kv-stage` control positions and staging.
`--kv-compact` is an additional approximate representation; it is not lossless
offload. None makes GPU-resident dense body weights disappear. Windows/WSL
shared-memory spill also does not provide24GB-class GPU bandwidth.

Native serving includes POSIX socket/mapping code. The existing WSL distro
has no CUDA compiler or C++ build toolchain. Porting or installing that stack
alone would not fix the target's dense-weight placement constraint.

The author's separate llama.cpp-tq3 fork has CPU kernels and layer offload for
TQ3_4S. We select it as an explicitly different, practical10GB experiment using
the same published weights. That path tests model compression/placement, not
azllm's DFlash2 acceleration. A future dense-layer streaming port would require
bounded host/staging allocation, graph-safe lifetime, peak-memory tests and
token equivalence checks; replacing all allocations with managed memory is
not a validated optimization.

## Comparison with Strata and the working setup

| Approach | What makes it fit / faster | Main local limitation |
|---|---|---|
|Current llama Qwen35B-A3B Q4|MoE experts mostly inRAM, GPU attention, CPUq8KV, mmap|Long editor prefills and instruction/code errors remain; working128K API.|
|Strata, sameQwen Q4|Different expert/prefill scheduling and GPU KV|Faster32K single cases; SQL regression; no128K Qwen validation.|
|Strata Flash-Next|SSD/RAM/GPU expert tiers, bounded RAM, optionalMTP, hostKV|Fits10GB but four coding deadlines; original51K workflow empty final.|
|azllm27B + DFlash2|Dense target onGPU, low-bit weights/KV, speculative verification|Published target exceeds10GB; no general dense CPU layer path found.|
|llama.cpp-tq3 +27B|Same TQ3_4S file with CPU/GPU layer split|Dense CPU work loses the all-GPU speed premise; local trial required.|

Strata has no hard12GB gate in the pinned version. Its custom Windows fork
made optionalMTP metadata optional and reduced copied-GGUF resident pressure.
MTP consumed GPU room otherwise used for experts and prefill: a high accepted
draft percentage did not make Flash coding finish. That is directly relevant
to the article: speculation has a memory cost and must be measured end to end.

The embedded froggeric-v22 template maps both high and xhigh to an added
natural-language effort instruction. That is a real prompt difference, not
proof of a distinct trained effort control or of better answers. It also adds
warnings after tool-error text. Record the template hash when comparing to
the older dense Q6/Q8 results; the format is not the only variable changing.

No cache provides permanent memory of all instructions. Clients must actually
send/read the files, preserve needed history and stay within input/output
budgets. Sleeping/restarting the current server unloads KV; the next request
must resend history. A changed file must be reread and its new bytes delivered.
